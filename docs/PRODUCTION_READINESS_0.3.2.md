## Fix and evidence boundary

Android's ICU regular-expression engine rejects the JVM-only `(?U)` flag used by dictionary query normalization. This made dictionary lookup fail on Android despite desktop unit tests. [Fix commit a6c99f3](https://github.com/sainadh812/ReadFlow/commit/a6c99f33f6e8934f4a304355a3e093b1b569dfa8) replaces that flag with an explicit whitespace, Unicode-separator and NEL character class. Regression coverage includes Unicode whitespace and a real Android seeded-dictionary lookup.

The targeted desktop `DictionaryQueryTest` passed **10 tests**, and the corrected expression passed a native ICU probe on the host for **25 whitespace characters**. Actual Android 15 emulator instrumentation subsequently passed normalization and installed-dictionary lookup: `curiosity` returned **three entries**, `error=null`, phase `READY`, and seed status `complete`. Voice and alignment packs were also installed and verified. See the [Android seed result](evidence/reader-0.3.2/android-dictionary-seed.json), [build provenance](evidence/reader-0.3.2/android-dictionary-build.json) and [regression summary](evidence/reader-0.3.2/dictionary-regression-summary.json).

This result used the reviewed application source in an x86_64 emulator release runtime with local debug signing and Firebase unconfigured. It establishes the Android dictionary regression result; it is not physical-device or Play-installed ARM64 verification. The later recording script could not find `PDF view` during navigation and produced no clips. That separate media failure does not invalidate the dictionary result; store screenshots, videos and background-playback proof still need successful capture and review.

Compared with the signed 0.3.1 application's source revision `94006546634355658abfba7ce1a7a442d8825828`, the sole change under `app/src/main` and `app/src/release` is `DictionaryModels.kt`. No privacy, model, dictionary-pack, font or license asset changed in those source trees. The Gradle version and test/capture infrastructure also changed. The new signed files were independently verified as described below. The separate Android dictionary runtime result is tied to these reviewed source trees by the saved emulator build provenance.
